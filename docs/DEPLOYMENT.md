# Deployment Guide

## Local development

1. Install the current Node.js LTS and package manager selected by the repository.
2. Install dependencies.
3. Run Astryx CLI initialization as directed by its current documentation.
4. Create `.env.local` from `.env.example` with a server-only Turso URL and token.
5. Run migrations against a disposable local database or explicitly selected development database.
6. Start Vite development server and run tests.

For authenticated development, set `VITE_OPENAUTH_ISSUER` for the browser and `OPENAUTH_ISSUER` for the API, then run `npm run dev:full`. The local OpenAuth server is started by `npm run dev:auth`.

Do not place `TURSO_AUTH_TOKEN` in a `VITE_` variable or client bundle.
Do not place OpenAuth signing keys, auth storage, or verification secrets in `VITE_` variables. The browser only receives the public issuer URL.

## Turso

Use a separate development database and production database. Apply migrations in order, record the migration version, and verify with a read-only health query. Follow Turso's current CLI guidance at <https://docs.turso.tech/tursodb/quickstart>.

The token included in the original project brief must be considered exposed. Revoke/rotate it before any deployment and store the replacement only in local secret storage and Vercel environment variables.

## Vercel

- Connect the Git repository and use the Vite build command generated by the project.
- Configure production and preview environment variables separately.
- Run migrations through an intentional release step, never automatically on every request.
- Enable preview deployments against a non-production database.
- Configure a custom domain and HTTPS before sharing the app.
- Confirm server functions can reach Turso from the deployment region.

## Release checklist

- [ ] Production backup/export completed.
- [ ] Migration tested on a copy.
- [ ] Environment variables verified without printing values.
- [ ] Health endpoint passes.
- [ ] Critical browser journey passes on preview.
- [ ] Rollback commit and migration plan documented.
